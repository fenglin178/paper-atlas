Efficient Streaming Language Models with Attention Sinks

为什么普通 Sliding Window 在移除最初几个 token 后出现严重性能崩溃？StreamingLLM 通过保留初始 KV 与滚动窗口，使预训练模型能够以固定缓存持续处理文本流。

核心摘要

一句话概括

大模型的若干 Attention Head 往往持续关注序列开头的 token。普通滑动窗口删掉这些 token 的 KV 后，注意力重新归一化并可能导致预测质量崩溃。StreamingLLM 固定保留少量初始 Sink KV，同时仅缓存最近的内容 KV，从而实现固定缓存大小的持续流式推理。

概念边界：支持累计数百万 token 的流式处理，不等于能够同时访问数百万 token 的全部历史。已被驱逐的中间 token 通常无法直接参与后续注意力计算。

全文区分论文直接实测、合理的机制解释和延伸假说。交互图使用人为示例，实验表格注明论文来源。

01 / Research Problem

自回归 Transformer 生成第 t+1 个 token 时，需要使用之前 token 的 Key 与 Value。为了避免重复计算，推理系统保存每层的 KV Cache；若保留全部历史，显存随累计长度线性增长。常规滑动窗口限制了显存，却在初始 token 被删除时出现异常的 PPL 恶化。

MKV = 2 · L · T · Hkv · dh · b

MKV 为单序列缓存字节数；L 是层数；T 是缓存 token 数；Hkv 是每层 KV head 数；dh 是每个 KV head 的维度；b 是每个值所用字节数；2 对应 K 和 V。公式忽略内存管理等额外开销。

例如 Llama-2-7B 的传统多头注意力采用 32 层、32 个 KV heads、每个 head 128 维，FP16 时每个 token 全层 KV 约占 0.5 MiB。完整缓存 65536 tokens 理论上约占 32 GiB（仅 KV）。

研究问题：已训练的有限上下文 LLM，能否不重新训练、不无限增长缓存，也不反复重算全部窗口，从而持续处理新的文本？工程收益是限制显存和每 token 的注意力开销；机制价值是揭示初始位置的特殊作用。

02 / Prior Work

已有路线解决的问题对持续流式推理的局限
Longformer / BigBird局部、全局及稀疏注意力结构通常需要特定模型结构与训练适配
FlashAttention提高精确注意力的 IO 效率不会自行消除全部历史 KV 的线性增长
ALiBi / Position Interpolation位置编码与长度外推、上下文扩展扩展窗口不等于无限时间的固定缓存
Sliding Window + Re-computation每次重新使用最新局部窗口反复计算 KV，推理成本高
Quantizable Transformers讨论 Attention Head 的 No-op 与特殊注意力分配没有直接提出本文的预训练模型流式缓存方案

本文增量：将初始位置异常高注意力、缓存驱逐后的模型崩溃，以及无需微调的固定 KV Cache 方案连接起来。

03 / Core Intuition

为什么 Softmax 会产生“概率汇聚点”？

atj = exp(stj) / Σk∈Ct exp(stk),　Σj∈Ct atj = 1

t 是当前 Query 位置；j、k 是允许访问的 Key 位置；Ct 是缓存与 causal mask 允许的 Key 集合；stj 是 Query-Key 打分；atj 是注意力权重。Softmax 将当前行的权重归一化到 1。

模型即使没有明显需要读取的内容，常规 Softmax 仍须分配全部概率。初始 token 对所有后续 Query 可见，因此是一个可能的稳定汇聚位置。大量 Head 会对这个位置分配高注意力，这称为 Attention Sink。

注意力头输出为加权的 Value 和：ot = Σj∈Ctatjvj。其中 ot 是该头的输出向量，vj 是位置 j 的 Value。删除高权重 Key 会改变其他 token 的归一化权重，因而可能显著改变 ot 和后续预测。

证据边界：公式证明了重归一化的数学效果，但模型在真实任务中是否崩溃，需要通过实际实验验证。Softmax 约束与初始位置可见性是机制解释，不构成所有模型中 Sink 形成的充分必要条件证明。

首 token 为什么特殊？

在 causal attention 中，第 j 个 Key 可被位置 j 到 T 的 Query 访问，一共有 T−j+1 个；第一个 token 被全部 T 个 Query 访问，因此有更稳定的训练机会。但这不意味着 Sink 一定包含关键语义信息。

04 / Method · StreamingLLM

完整 Pipeline

Input：持续到来的 token → 各层生成 Q/K/V → KV Selection：固定 Sink + 最近 Rolling Window → Position Encoding：使用与缓存连续位置一致的 RoPE/ALiBi 处理 → Attention：Query 读取保留 KV → Output：预测下一个 token，并驱逐最旧的普通 KV。

设 S 是始终保留的初始 token 数，W 是滚动缓存数。当前缓存保留初始 S 个位置，以及最近最多 W 个位置，因此占用不超过 S+W 个 token 的 KV。论文在多个模型的默认配置中发现保留前 4 个 token 已足以恢复稳定困惑度，但 4 并非理论常数。

为什么还要重新处理位置？

如果跳过了中间历史 token，缓存中的原始绝对位置就出现间隔。论文采用连续缓存位置映射。RoPE 使用与位置有关的旋转矩阵作用于 Query 和 Key，因此旧的已旋转 Key 不能不加处理就当作新位置的 Key；论文讨论了缓存旋转前的 Key，再根据更新后位置应用 RoPE。对 ALiBi 则可在 Attention Logits 中按缓存内距离计算偏置。

固定 W、S 时，每个新 token 在每层读取的历史 KV 数量有固定上限，因此累计 T 个 token 的核心注意力读缓存开销近似为 O(T(S+W))；相较于每一步完整重算窗口的做法，避免了重复构建窗口内的 KV。这里的 O 是渐近复杂度符号，T 为累计 token 数，并省略隐藏维度、层数及其他成本。

训练阶段专用 Sink Token

除现有预训练模型的推理方法外，作者还从头训练小型语言模型，比较 Vanilla、Softmax-off-by-One / Zero Sink 与 Learnable Sink。专用可学习 Sink 让模型更容易以一个固定位置吸收注意力，而不依赖多个自然初始 token。

06 / Reviewer Assessment

Strength 1 · 识别并验证异常：对初始 KV 的驱逐、恢复和内容替换构成了较完整的实验证据链，超出了仅观察 attention map。

Strength 2 · 机制带来工程价值：固定数量初始 KV 与近期 KV 的简单规则，可直接作用于已训练模型，并获得可衡量的推理效率收益。

Limitation 1 · 机制不完全：Softmax 归一化、因果可见性和 Sink Key/Value 的关系尚未充分分离。高权重不自动等价于重要语义或大的最终 logit 贡献。

Limitation 2 · Streaming ≠ Long-context retrieval：它解决的是固定缓存下持续局部建模；完整历史检索、全局长距离推理需要额外的记忆或检索设计。

Limitation 3 · 可迁移性：若干实验以当时的模型、架构与特定 PPL 基线为依据；在新一代位置编码和 KV 压缩策略中，最优 Sink 数量与保留策略需要重新测试。

综合评价

本文的主要创新是把对 Attention Sink 的机制观察变成无需微调的、可部署的流式推理缓存策略。最值得后续研究的不是再证明 Sink 存在，而是解释各层各头的 Sink 所承担的具体计算角色。

07 / 可复现的研究延伸

可以在 GPT-2 或 Pythia 等 Decoder-only 模型中，对每个 (layer, head) 计算平均初始位置注意力占比：

Rl,h = (1 / |Q|) Σt∈Q Σj=0S−1 Al,h,t,j

Rl,h 是第 l 层第 h 个 Head 的平均 Sink 权重；Q 是所选 Query 位置集合，|Q| 是其数量；S 是初始 Sink 位置数；Al,h,t,j 是 Query t 对 Key j 的注意力权重。建议剔除靠近序列首部的 Query，避免因 causal mask 造成系统性偏差。

待验证假设：Sink attention 比例高的 Head，可能更倾向于提供注意力归一化稳定性；但它的最终下游因果贡献不一定更高。可将 Sink Ratio 与 JS 距离、头消融 ΔLoss、Sink KV 替换干预相关联。这里的 R 指标和研究假设是阅读后的研究建议，不是原文提出的冗余指标。

尤其要注意：BERT 是双向 Encoder，与 Decoder-only 模型的因果可见性不同，不能直接移植首位置的同一种形成解释。
